# Editing

Everything the editor does: links, embeds, properties, tasks, tables, bases, daily notes, the planner and the writing views.

The open note shows as a tab in the header: its name, and × to close it. Click the name to rename or move the note (the full path shows while you edit; Enter saves, Esc cancels). The sidebar lists what's inside the vault's single top folder (`content/`) as the top level.

Source mode (CodeMirror 6): headings, emphasis, links, `[[wikilinks]]`, `==highlights==`, footnotes and YAML frontmatter are styled but stay as text. Type `/` at the start of a line or after a space for the formatting menu (tables, tasks, callouts, code blocks and so on); keep typing to filter. The list is in `src/slash.js`.

On a phone, a bar sits above the keyboard while you type (`src/kbbar.js`): **/** opens that menu, **☐** turns the line into a task (or back), **H** cycles heading levels (# to ### and off), **[[** adds a note link with the cursor inside, and **↶** undoes. Swipe the bar sideways, as in Apple Notes, for every other menu command (headings, lists, bold, callouts and so on; the table ones appear with the cursor in a table). Bold, italic and the like wrap selected text, and line-level commands start a new line when the cursor is mid-text.

Links are clickable (`src/links.js`). Web links, bare URLs and `<autolinks>` open in a new tab; `[[wikilinks]]` and markdown links to `.md` files open that note, found by relative path, then any note with that name, and Back returns. A `[[link]]` to a note that doesn't exist offers to create it next to the current note. Clicking a link the cursor is already in just places the cursor, so the first tap opens and the next one edits the text; Ctrl/Cmd-click always opens. Only `http`, `https` and `mailto` links leave the app. Footnotes work too: clicking `[^1]` jumps to its `[^1]:` definition, and clicking the definition's marker jumps back. Links to a heading (`[[Note#Heading]]`, `[[#Heading]]`, `[text](#heading)`) scroll to that heading.

Callouts written `> [!type]-` start folded and `> [!type]+` start open; the chevron after the title folds or unfolds them without changing the note. `%% comments %%` are shown dimmed.

Image links to web addresses (`![alt](https://...)`) show the picture under the line; `![alt|300](url)` sets the width. They load from their own sites with no referrer, and don't show offline unless the browser has them cached. Vault attachments show too: `![[pic.png]]`, `![[pic.png|300]]` or `![](attachments/pic.png)` draw the image, audio and video get player controls, and a PDF shows as a card that opens it in a new tab. They're found next to the note, then from the root, then by name, fetched through the Worker, and kept in the browser's cache by version, so one you've opened shows offline. wr1t3r only ever adds pictures (see Pasting below); it never changes or deletes an attachment. Clicking a tag (a pill in the properties or a `#tag` in the text) lists the notes with it in the sidebar; typing `#tag` in the search box does the same, including nested tags like `#tag/sub`. Block ids (`^quote-1` at a line's end) are dimmed, and `[[Note#^quote-1]]` jumps to that line. Inline footnotes `^[...]` and raw HTML tags are styled.

A line holding just `![[Note]]` shows that note in a box (`src/embeds.js`); `![[Note#Heading]]` shows that section and `![[Note#^id]]` that block. The box is read-only: click its title to open the note, or put the cursor on the line (or press ✎) to edit the embed. Embeds inside an embedded note stay as text, so notes that embed each other can't loop.

**Settings** (the gear button, or palette "Settings"): a window over the page with tabs down the side: Appearance, Writing, Focus, Tasks and daily note, Home, Hotkeys, and Sync and files. The search box above the tabs shows matching settings from every tab, commands included, so typing "goal" or "grammar" goes straight to the row. Palette commands "Settings: Writing" and so on open one tab, so each can have a hotkey. On a phone the window fills the screen and the tabs are a list. Settings apply at once and are kept per device; the last tab used is remembered.

**Live Preview** (Settings > Appearance > Markdown symbols, on by default; **Always show** turns it off on that device) hides `**`, `##`, `[text](url)` parts, `[[`/`]]` and `==` on every line except the one the cursor is on (`src/livepreview.js`). Code blocks, tables and the properties box are left as they are. The note's text never changes.

**Writing help**, each with an On/Off switch in **Settings > Writing** (on to start, remembered per device):
- **Spellcheck** underlines misspelled words with the browser's own dictionary; right-click one for suggestions.
- **Smart punctuation** turns `"` and `'` into curly quotes as you type, `--` between words into an em dash and `...` into an ellipsis (`src/writing.js`). Backspace straight after one puts back what you typed. It never touches code, the properties, `[[links]]`, link addresses or HTML tags.
- **Formatting toolbar** (wide screens; phones have the keyboard bar), laid out like a word processor's: undo and redo; the font and text size; heading level, bold, italic, strikethrough, highlight, underline, text color, alignment and inline code; link, picture and table; bulleted and numbered lists, checklist and quote; **Insert** (callout, code block, divider, footnote, note link, today's date); then look up and print or export (`src/toolbar.js`). Each writes the same markdown its hotkey or slash command does. The font and size change how notes look on this device (markdown has no fonts of its own), so they apply to the whole note, not a selection.

**Pasting** formatted text (from a web page, Google Docs or Word) brings it in as markdown, keeping headings, bold and italic, lists, links, tables and web pictures (`src/paste.js`); inside code or the properties it stays plain, and Ctrl/Cmd+Shift+V always pastes plain text. **Pictures** pasted from the clipboard, dropped on the note, or picked with the toolbar's picture button are added to the vault and linked where they landed. The Worker reads the vault's `.obsidian/app.json` for the attachment folder and link style (`![[name]]` or `![](path)`), and names a pasted picture `Pasted image YYYYMMDDHHMMSS.png` (`src/pictures.js`). PNG, JPEG, GIF, WebP, AVIF and BMP up to 20 MB; adding one needs a connection.

**Page layout** is a setting, off to start (**Settings > Writing > Page layout**, the toolbar's page menu once it's on, or **Toggle page layout** in the command palette; per device). Off, notes look as usual and the toolbar has no page button. On, it shows the note on pages, as a word processor's print layout does, on a gray desk, with the header and footer in each page's top and bottom margins. Text stays inside the margins; a paragraph that runs off the bottom of a page carries on at the top of the next, split at a line as it wraps. **Page break** (in the toolbar's Insert menu and the slash menu) adds `<div class="pagebreak"></div>`, which starts a new page here, when printing, and in PDF and Word exports (Compile uses the same marker), and shows as a "Page break" rule. The page menu, and Settings > Writing under the switch, set the paper (Letter, A4, Legal, A5, or 6 × 9 in), portrait or landscape, and the margins (1, 0.75, 0.5 or 1.5 in); printing and the PDF and Word exports use that page whether page layout is on or off (`src/pagelayout.js`, `src/pageview.js`). **Header and footer** (Settings > Writing, or **Header and footer…** in the page menu) are a line of text each for the top and bottom margins; the footer starts as `{page}` and the header empty. `{page}`, `{pages}`, `{title}` (the note's name, or the compile title) and `{date}` fill in, and `|` splits a line into left | right or left | center | right. They show on the pages on screen, in print and PDF (as the page's margin boxes), and in Word (as its header and footer, with live page numbers); a compiled title page has none. The pages on screen are a close match for print, not an exact one: on a column narrower than the paper the lines wrap sooner, and lines far off screen are placed by estimate until you scroll to them. The note's text never changes.

**Track changes** (the toolbar's Review button, or **Track changes** in the command palette; per note, on this device): while it's on, what you type is underlined in green and what you delete is struck through in red instead of disappearing, as in Word. Deleting text you added yourself just removes it, and backspacing into struck text steps over it. The changes are stored in the note as CriticMarkup (`{++added++}`, `{--deleted--}`, `{~~old~>new~~}`), so they sync like any edit and other markdown apps show them as that markup. The markup is hidden here; the cursor steps over it.
- Right-click a change to accept or reject it, or all of them. The Review menu also has next and previous change, accept or reject at the cursor, accept all and reject all (each one undoable), and **Show as final**, which hides the changes to show how the text will read.
- **New comment** (Review menu or palette) marks the selected text and adds a comment, `{==text==}{>>comment<<}`, shown as 💬 (hover to read it; put the cursor on it to edit it; right-click to resolve it). Where the editor is wide enough (700px and up), the text makes room on the right and each comment is also a card in the margin, level with its line, quoting the text it's about. Click a card to edit the comment; **Resolve** removes the comment and its highlight and keeps the text (undo brings it back).
- Only typing, pasting, dropping and deleting are tracked; formatting commands, ticking tasks and the like change the text as usual. Exports, compiles and printing use the text with every change accepted and comments left out (`src/trackchanges.js`, `src/trackview.js`).

**Export or print a note** (the toolbar's printer button, or the command palette) opens the Compile dialog for just that note: Markdown, HTML, Print / PDF (the browser's print dialog), or Word, with an optional title page.

**Quick switcher and command palette** (`src/palette.js`): **Ctrl/Cmd+O** jumps to a note by name (recent ones first; letters in order are enough, so `chone` finds Chapter One), and offers to create the note when nothing matches. **Ctrl/Cmd+P**, or the ⌘ button in the header, runs any command: new note, today's note, templates, bookmark, rename, delete, close tab, reference pane, Contents, Live Preview, upload, clip, media notes, sync, the focus timer, find, and every formatting command from the slash menu. Default hotkeys (Ctrl/Cmd+B bold, +I italic, +K link, +Enter checkbox, +D delete the line, +] / +[ indent) and can be changed in **Settings > Hotkeys**; on a Mac, Ctrl+Enter works for the checkbox too.

**Templates** (`src/templates.js`): **New note from template** and **Insert template** (both in the command palette) list everything in `_templates/`. A new note is named first; inserting puts the template's text at the cursor and adds only the properties the note doesn't have yet. Templater tags (dates, the title) and `{{title}}`, `{{date}}`, `{{time}}` and `{{date:FORMAT}}` are filled in without running anything; plugin fields like `{{LIST:director}}` come out empty. The `_templates` folder stays out of the notes list; **Settings > Templates** lists the templates and opens, renames, deletes or adds them.

**New notes that file themselves** (`src/newnotes.js`): **New journal entry**, **New microblog post**, **New note in Notes**, **New book log**, **New movie log**, **New TV series log**, **New music log**, **New game log** and **New podcast log** in the command palette ask for a title, fill in that template (`Journal`, `Microblog`, `Note`, `Book`, `Movie`, `Series`, `Music`, `Game`, `Podcast`) and save the note in its folder: `journal/`, `microblog/`, `notes/`, or `logs/books/`, `logs/movies-tv/`, `logs/music/`, `logs/games/` and `logs/podcasts/` (the same folders as the media lookups, so the Worker's `MEDIA_*_FOLDER` settings move both). A name that's taken gets a number. **New note from template** files those templates the same way. Each can have a hotkey or a Home tile like any command. They make a blank log to fill in by hand; **Create book note** and the other lookups fill one in from the web.

**Archived notes:** a note with `archived: true` in its properties, or `status: archived`, is left out of the notes list. Search still finds it (marked *archived*), and searching `archive` on its own lists every archived note first. **Archive** in a note's right-click menu in the sidebar (or **Archive this note** in the command palette) sets `status: Archived`, replacing any other status; **Archive folder** does it for every note in the folder after asking. **Unarchive** (and **Unarchive folder**, once everything in it is archived) empties the status, or takes an older `archived: true` line off.

**Bookmarks and tags:** the ☆ in a note's tab bookmarks it; bookmarked notes are listed at the top of the sidebar (on this device). Below them, **Tags** lists every tag with how many notes have it; click one to see them.

**Tabs:** every note opened from the sidebar (or New, Today, a search) gets a tab across the top; following a link opens it in the current tab. Close a tab with × (or a middle-click). Open tabs are remembered on the device. On a phone only the current tab shows, and the number beside it lists the others. Folders in the sidebar stay open or shut as you leave them (remembered per device): opening a note (Today included) or a sync never opens one; making a note in a folder, or a folder tile, does. Opening a note from inside folders in the sidebar folds those folders back up behind it.

**Reference pane** (wide screens): the split-square button in the header shows another note, read-only, beside the one you're editing. Pick it from the list at the top (your open tabs); links clicked in it open in the pane; **Edit** makes its note editable where it is: the editor and the pane trade sides, so neither note moves, and the note you were editing shows in the pane.

The search box takes operators (`src/search.js`): words (all must appear), `"a phrase"`, `path:folder`, `file:name`, `tag:x` or `#x` (nested tags count), and `-word` to leave notes out. Results show the first matching line with the match marked.

Typing `[[` lists notes to link to, filtered as you type (`src/linkcomplete.js`); picking one writes the shortest name that finds it, and `#` after a name lists that note's headings (`[[#` this note's). Links to notes that don't exist yet are drawn fainter. Under a note, a links panel (`src/backlinks.js`) has three parts that fold: **Linked from** (notes that link to it, with the line each link is on), **Links to** (notes it links to, faded when they don't exist yet) and **Unlinked mentions** (notes that name it in plain text without linking it; folded at first). It's built from the notes on the device, so it works offline. Renaming a note (edit the name in its tab) rewrites the links to it in other notes after asking, changing only the name part of each link and keeping its headings, aliases and style (`src/vaultlinks.js`).

Frontmatter shows as a **Properties** box (`src/frontmatter.js`, `src/properties.js`). It starts hidden, as a small **Properties · 4** button at the top right of the note: tap it to show the box, and **▾ Properties** to hide it again (remembered for that note until the page reloads). Notes in `logs/`, `sketchbooks/` and `catalog/` open with it showing, and a planner page hides it with no button, since the planner's header has one. The box is drawn over the YAML, so the cursor, typing and Backspace never reach it: each property is a row with a control for its type: **Text** (a box that grows with its text), **List** (pills, in the tag colors, with **+ add**: Enter or comma adds, × or Backspace in the empty box removes), **Number**, **Checkbox**, **Date** and **Date & time** (pickers). `tags` are pills too, and tapping one shows the notes with that tag. Tap a property's name for **Rename…**, its type, and **Remove** (Ctrl/Cmd+Z brings it back). Changing the type converts the value (text "a, b" becomes the list a, b; a list becomes "a, b"; yes/true becomes a ticked checkbox) and applies to that name in every note (for a property the website reads, like `publish`, `date` or `eyebrow`, it asks first, since a new shape can change how the site shows it): the types are kept in `_wr1t3r/Property Types.md` beside the Home note, so they sync. A name with no type set gets one from its value, as before. **+ Add property** (or **Add property** in the slash menu) asks for the name, with the vault's names offered, and the type, which starts as the name's own type; the row is drawn with its control ready, a list with its **+ add** box. A note with no properties shows **+ Properties**, which does the same. Values the box can't edit (nested maps, multi-line text, Templater's `<% %>`) show as YAML; **Toggle source** in the box's header shows all the properties as YAML text to edit, and again to go back. Each edit rewrites only that property's lines, keeping its quotes, capitals, list style and date format; other keys and their order are never touched. **New** notes (outside `_` folders) start with the vault's Note template properties (`title`, `publish: false`, `tags`, `status: seed`, today's `date`, `sticky`, `eyebrow`), so the site has a fixed date instead of falling back to the file's creation time, which changes on every build.

**Clean up properties** (command palette; `src/propclean.js`, `src/propcleanview.js`) lists every property in the vault with how many notes use it and how many of those leave it empty. **Clear empty** takes a property out where it has nothing in it (`key:`, `key: ""`, `key: []`, a list of only blank items) and drops blank items from its lists; **Clear all empty values** does that for every property at once. **Rename…** renames a property in every note; naming an existing property merges into it: an empty one gives way, and so does one with the same values (in any order, like a `genres` list that repeats `genre`). Notes where both have different values are left alone and listed, with **Combine their values** to make one list of both (the target's own first, no repeats). Renaming `genres` to `genre` this way leaves the website exactly as it was, since the site already reads `genres` only where `genre` is empty. **Delete** takes a property out of every note, values and all. Each shows the notes it would change, with the lines that go and come, and writes only when you confirm (Delete asks twice). Only those lines change; the rest of each note stays byte for byte. Templates and wr1t3r's own files aren't touched. Changes sync like any edit, so they can't be undone from wr1t3r, but the Google Drive backup (below) keeps earlier versions of each file.

- **Published sites.** In the personal build, properties its website reads are listed in `src/sitekeys.js` and marked **site**; Rename or Delete of one shows a warning and asks again. Other builds have no such list.

**Banners and covers** (`src/pretty.js`) use the Pretty Properties plugin's default property names. `banner:` draws a wide picture across the whole note pane, faded at the bottom; `banner_position:` (0 to 100, default 50) picks which part shows, and the banner's **Reposition** button lets you drag the picture up or down to set it. `cover:` draws a picture to the left of the properties box, which grows to fit it; the Media Notes plugin's `coverImage:`, the older `image:` and `thumbnail:` work too (the first one set wins). `cover_shape:` takes Pretty Properties' shapes (`initial`, `initial-2`, `initial-3`, `vertical-cover`, `vertical-contain`, `horizontal-cover`, `horizontal-contain`, `square`, `circle`) and `cover_position:` `left`, `right`, `top` or `bottom`. On a phone the cover sits above the properties, and hiding the box hides it. An image can be a web address, `[[a vault file]]`, `[text](path)`, a bare vault path, or a YouTube link (its thumbnail). The image properties (`banner`, `banner_position`, `cover`, `coverImage`, `image`, `thumbnail`) stay out of the properties box until you click the banner or cover (click again to hide them); **Image properties** next to **+ Add property** shows them too, for a picture that doesn't load. **Banner image** and **Cover image** in the slash menu and command palette open that property's box for typing, adding it if needed.

Blocks are drawn like what they are, with the markdown still showing (`src/blocks.js`): task boxes are real checkboxes (clicking one flips `[ ]` / `[x]` in the text, and done tasks are struck through; ticking adds the day it was done in the Tasks plugin format, `✅ 2026-09-30`, before any `^block-id`, and unticking takes it off, `src/tasks.js`; turn it off under Settings > Tasks and daily note; checklists sort themselves too, see below), callouts get a colored box in a color for their type with its icon in place of `[!type]` (Backspace just after the icon removes it, to change the type), quotes a side bar (the `>` markers are always hidden; the darker left edge stands in for them, and Backspace at a line's start still removes one), code blocks a shaded box, and `---` a rule.

**Due dates** (`src/due.js`): **Due date** in the slash menu (also on the keyboard bar's swipe list and in the command palette) opens a date picker for the task on the cursor's line, making the line a task first if it isn't one; right-clicking a task's box offers Due today, tomorrow, in a week, a picked date, or removing it. The date is written in the Tasks plugin format, `📅 2026-10-03`, before any `✅` done date or `^block-id`. It shows as a pill: red once the day has passed while the task is open, accented on the day itself; clicking the pill picks a new date (clear it in the picker to take it off).

**Master task lists** (`src/tasklists.js`, `src/tasklistview.js`), Emergent Task Planner style: **Critical Tasks** and **To Do's** in the slash menu add a ```` ```wr1t3r-tasks ```` block showing every task tagged `#crit` or `#todo` (nested tags like `#crit/work` count) from across the vault, wherever it's written. In a daily note (named `YYYY-MM-DD` or `YYYY.MM.DD`) the block shows that day's tasks: due that day, done that day, or written in that day's note, plus open tasks that are overdue when the day is today. Put the blocks in `_templates/Daily.md` and every daily note gets both lists for its own day.

**Lists** are the same card for any tag: `- [ ] coffee filters #shopping` in any note is on the **Shopping** list, and `#wishlist`, `#packing` or any other tag works the same. `/list` (or **Insert list**, or **+ Add a list** on Home) picks a list, or makes one from a name you type (Wish list → `#wish-list`). A card can show several lists (`list: [shopping, wishlist]`, or ⚙ to tick them): **grouped** under each list's name, or **in columns** side by side that stack when there's no room, each with its own add box. Items added from a card go into the list's own note in `_docs/` (`Shopping.md`), made the first time. Day filters and due dates are the task lists' (`#crit`, `#todo`); other lists show every item. A card combining the two task lists is called **Tasks**; the planner can show one with `tasks: [crit+todo]`. The ⚙ menu also renames the card, and its dot sets a color.
- Ticking a task ticks its real line, with the done date. Right-click one for Due today, tomorrow, in a week, or removing the date, or to open its note; the note's name beside a task opens it too.
- **Add to the …** at the bottom writes `- [ ] text #crit` (due that day, in a day's view) at the end of the list's own note, `Critical Tasks.md` or `To Do's.md` in `docs/`, made the first time (moved elsewhere, it's found by name; the older `… List.md` names still count). An `inbox: "[[Some note]]"` line sends them elsewhere.
- **⚙** sets the block up with no code: which list (or any other tag), open, done or both, this day's tasks or every task, grouping (none, by note, by due date: overdue and today first) and sort (due date, note, text). Each choice writes one YAML line in the block (`list: crit`, `show: all`, `group: due`); **</>** shows them. The tasks themselves stay ordinary Tasks-plugin lines.

**Sorting checklists** (Settings > Tasks and daily note > Sort checklists, on to start; per device): when a note opens, or a sync brings in a new version of the open one, done tasks move below the rest of their list, keeping their order, with everything indented under an item moving with it; sub-lists sort the same way. It waits until a sync has finished, so it works on the vault's latest text and doesn't race an edit coming from another device, and the note is only written when the order changes (Ctrl/Cmd+Z puts it back). Numbered lists, code blocks, a `# Timeline` section (which stays in time order), and notes in `_templates/`, `_clippings/` and `_uploads/` are left alone, and a blank line ends a list. **Sort checklists** in the command palette does it on demand (`src/tasks.js`).

**Upload** turns files into notes in `content/uploads/`, with a small frontmatter block naming the source file. Word (`.docx`), PDF, HTML and text files are converted in the browser, so this works offline too. Headings, lists, links, bold/italic and tables come across; images are left out. PDFs give their text layer only, with paragraphs and headings guessed from the layout, so a scanned PDF comes out empty.

**Clip** saves a web page as a note in `content/docs/clippings/`, with Web Clipper-style frontmatter (`title`, `source`, `author`, `published`, `created`, `description`, `tags: clippings`). Mozilla's Readability picks out the article and it's stored as markdown; links and images point at the original site.

The **Clip to wr1t3r** bookmarklet in **Settings > Sync and files** works on every build, Dropbox and Drive included, with no server involved. Click it on the page you're reading: it copies the page as your browser has it (so pages you're signed in to come out whole), leaves out scripts, styles, forms and embeds, compresses it and opens wr1t3r in a new tab at `#clip-page=…` (`src/clippayload.js`). wr1t3r asks before saving it, since anyone could make such a link. Select some text first to clip only that part. A page that's still too big once compressed (over 1 MB) asks you to select the part you want. On desktop, drag the bookmarklet to the bookmarks bar. On a phone, tap **Copy** beside it, bookmark any page, then edit that bookmark and paste over its address; Chrome on Android runs it when you type the bookmark's name in the address bar and pick it.

On the Worker build the **Clip** button (and Commands > Clip a web page) takes an address instead, and the Worker fetches the page (Reader's `/api/fetch` rules: public http(s) addresses only, 5 MB, 15 s, token required); pages behind a login or built entirely by JavaScript may come out thin that way. Bookmarklets saved before `#clip-page=` send `#clip=<address>`, which still goes through the Worker.

**Settings > Appearance** (the gear button) sets the theme, kept per device; on a phone, or with the toolbar off, it has the font and text size too. Themes are Default (Reader's colors), Gruvbox, Dracula, Rosé Pine, Tokyo Night, Catppuccin, Kanagawa, Everforest, Nord, Monokai, SynthWave '84, and wr1t3r's own Bubblegum (candy pink) and Shire (earth tones on parchment); each but Monokai and SynthWave '84 (dark only) has Light and Dark variants (Dracula's light one is Alucard, Rosé Pine's is Dawn, Tokyo Night's Night and Day, Catppuccin's Mocha and Latte, Kanagawa's Wave and Lotus, Nord's light one uses its Snow Storm colors, Bubblegum's dark one is Bubblegum Night, Shire's is Shire Night), and Auto follows the system. Top-level folders in the sidebar take the theme's rainbow colors in turn, and their subfolders keep the same color. The same seven colors mark everything else that's color-coded, so it all changes with the theme: each tag has one (its pill in the properties, `#tag` in the text and its row in the sidebar's Tags), bookmarks take their folder's color, and list bullets and numbers change color with each level of nesting. **Headings** set to By level gives each heading level, `#` to `######`, its own of those colors, in the app and on the exported website. **Outlines** set to Bold draws thick outlines and hard offset shadows around buttons, cards, Home tiles, the daily planner's buttons and cards, menus and dialogs, over whichever theme is on, and gives the sidebar's buttons the rainbow colors (in the app only, not the exported website). On a light theme the outlines are the text color. On a dark one, colored things (tiles, sidebar buttons) get a light fill of their color outlined in a darker shade of it, and the rest are outlined in the accent color.

The bar under the editor shows the note's word count, leaving out frontmatter. Tap it to switch to characters. When text is selected, it counts the selection.

The bar also has a pomodoro timer. Tap it to start or pause, and tap ↺ to reset. Starting a focus block turns on focus mode; Esc (or Leave focus) leaves focus mode and the timer keeps running. By default a focus block is 25 minutes and a break is 5; change the lengths in **Settings > Focus**. When a block ends, wr1t3r plays a chime and tells you how many words you wrote during it. It shows a notification too if you allow them. On iPhone, notifications only work once wr1t3r is added to the Home Screen. The timer keeps its place when you switch notes or reload. While the phone is locked, it only catches up once you come back.

The calendar button in the top right opens your Google Calendar agenda: today and the next week, from every calendar ticked in Google Calendar. The header also shows today's next event. On a wide screen (1180px and up) the page has three columns: the notes list, the note, and a right column with the month calendar, the agenda and the Contents. The buttons at the two ends of the header fold the side columns away, the arrow beside Agenda folds the list under the calendar, and the calendar button brings the agenda back; each is remembered per device. Narrower screens keep the pop-over agenda, and the notes list can still be folded on anything wider than a phone. Calendar names that are email addresses are masked: your main calendar shows as "Main". On a computer (900px and wider) a month calendar sits above the list, with ‹ › and Today to change months and dots for each day's events: clicking a day starts the list there, and clicking an empty day opens the new-event form for it.
- Tap an event to put it in the open note as a line. Tap **Open in Google** to edit it there.
- The chips at the top pick which calendars show. Until you change them, they follow the calendars ticked in Google Calendar.
- Each event is tinted with its Google color: the color set on the event, or else its calendar's color.
- **+ Add event** adds an event to the calendar you pick (it remembers your last choice), with a reminder and a color you pick. The defaults are the calendar's own reminder and color. Events start as one-hour blocks: changing the start moves the end with it (keeping any length you set), and the end can still be changed on its own.
- **Delete** (open an event in the agenda) deletes it from Google Calendar after asking, only this occurrence of a repeating one, and takes its line off that day's planner Timeline if it was imported there. It's offered for calendars you can edit.
- Reminders pop up with a chime while wr1t3r is open, and as a notification if you allow them. When wr1t3r is closed, Google Calendar's own app does the reminding.
- Offline, it shows the last agenda it loaded.

Setting it up is covered under [Google Calendar](#google-calendar) below.

**Contents** in the bar under the editor lists the note's headings, indented by level. Tap one to jump to it. The heading you're reading is highlighted as you scroll, and the arrows fold a section's sub-headings. On a wide screen the list sits in the right column under the calendar (and stays open next time), and opening it folds the agenda to make room; on a phone it closes after a jump.

Tables are drawn as grids, with bold, code and links inside cells formatted (`src/tablegrid.js`); links in a cell open on click. Wide tables scroll sideways on a phone.

**Editing in the grid:** click a cell to type in it, like a spreadsheet: typing replaces what's there (click again or use the arrow keys to change it instead). **Tab** / **Shift+Tab** move across (Tab past the last cell adds a row), **Enter** and the up/down arrows move down and up (Enter on the last row adds one), the left/right arrows move to the next cell once the caret is at that end of the text (or straight away, while the whole cell is selected), **Esc** stops without saving that cell, and clicking outside the table saves it. While a cell is open, column letters and row numbers show around the table and a bar above it has **+ Row**, **+ Column**, **− Row**, **− Column**, **Markdown** (the table as text, with the cursor in that cell) and **Done**. A cell you change rewrites the table with its columns lined up; tables you don't touch are never reshaped.

**Formulas:** type `=` in a cell under the header to start one. Row 1 is the first row under the header (the header is row 0) and column A the first column, as the letters and numbers around the grid show. `=B1*C1` is a formula for that cell; typing `=...` into a cell as markdown works too, once the cursor leaves the table. Formula lines saved before this numbering (`wr1t3r formulas:` without `v2`) are read with their row numbers moved to match; `=B*C` (column letters with no row numbers) fills the whole column, each row using its own B and C, and a row whose B and C are empty stays empty. While typing a formula, clicking a cell adds its name (Shift-click makes a range from the name before the cursor). Ranges: `B1:B4`, and `B:B` for every row of column B except the header and the cell asking, so a total row can say `=SUM(D:D)`. Operators: `+ - * / ^`, `%` (`15%`), `&` (joins text), and `= <> < > <= >=`, with spreadsheet precedence. Functions: `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `COUNTA`, `COUNTBLANK`, `MEDIAN`, `PRODUCT`, `ROUND`, `ROUNDUP`, `ROUNDDOWN`, `INT`, `ABS`, `SQRT`, `POWER`, `MOD`, `IF`, `IFERROR`, `AND`, `OR`, `NOT`, `SUMIF`, `COUNTIF`, `AVERAGEIF`, `CONCAT`, `LEN`, `UPPER`, `LOWER`, `TRIM` (`src/formula.js`).
- Cells read the way a spreadsheet reads them: `$1,200.50`, `15%`, `**42**` and `-3` are numbers. Results borrow their look from the cells they come from (a currency sign and two decimals, percentages, thousands commas); other results show up to two decimals.
- The cells keep the results as plain text, so any other markdown app shows the numbers. The formulas are kept in one HTML comment right under the table, which those hide: `<!-- wr1t3r formulas v2: D = B*C; D4 = SUM(D:D) -->`. `D4 =` with nothing after it marks a cell you typed a value into, so its column's formula leaves it alone; **No column formula** in the bar removes a column's formula and keeps its numbers.
- Results are worked out again on every change in the grid. A table you edit as markdown is worked out again when the cursor leaves it.
- Adding or removing rows and columns from the bar moves formulas with their cells, like a spreadsheet; a reference to a removed cell becomes `#REF!`. The markdown-mode commands below don't, so a row added there can leave a one-cell formula like `D4 =` pointing at the wrong row (whole-column formulas are unaffected).
- Errors show in the cell: `#DIV/0!`, `#VALUE!` (text where a number is needed), `#REF!`, `#NAME?` (an unknown function), `#CIRC!` (a formula that needs its own result) and `#ERROR!` (a formula that can't be read; hover the cell for why). They're written as `\#DIV/0!` so they aren't read as tags.
- Other apps don't recalculate: an edit there leaves the old numbers until the table is next changed in wr1t3r.

**Sorting:** each header cell has a small sort button (it shows on hover, or always on touch screens). The first click sorts the rows A to Z by that column, the next Z to A, and the new order is saved to the note. Numbers sort as numbers, including ones like `$1,200` or `40%`, and empty cells go last. A row with a formula of its own, like a totals row, stays where it is. Column formulas follow their rows. A column that already reads in order shows ▲ or ▼.

**As markdown** (the Markdown button in the bar over a table you're editing): a fixed-width font until the cursor leaves it. Moving the cursor into a table with the arrow keys edits its first cell, or its last row coming from below, so a table stays a grid; search and undo still show the text.
- **Tab** and **Shift+Tab** move between cells and pad the columns to line up. Tab past the last cell adds a row.
- **Enter** at the end of a row adds a row below it.
- With the cursor in a table, the slash menu adds **Add row below**, **Add column after**, **Delete row**, **Delete column** and **Format table**.
- Nothing is realigned unless you use one of these, so saving doesn't reshape your tables.

Rename a note by editing its path in the header and pressing Enter. Folders are made by putting a `/` in a name.

In the sidebar, drag a note or folder onto another folder to move it, or onto the empty space below the list to move it to the top level. Right-click a note or folder (long-press on a phone) for **Rename…**, **Move to…** (pick a folder, or type a new one) and **Delete**; deleting a folder deletes every note in it. A folder's menu also has **New note here…**, which starts the name prompt in that folder. Moves and renames offer to update links to the moved notes, as a rename from the header does (`src/moves.js`). Like any rename, a move is a new note plus a delete of the old one, so a published note's site address changes with it. Attachments stay where they are, since wr1t3r only reads them.

**Icons.** **Icon…** in a note's or folder's right-click menu picks an emoji (or takes any you type or paste) to show before its name in the sidebar, bookmarks, search results and tabs; **Remove icon** takes it off. A note's icon is its `icon:` property, so it can be typed in the properties too and travels with the note. A folder's is kept in `_wr1t3r/Settings.md` under `icons:`, by the folder's path, and follows the folder when it's renamed or moved (`src/icons.js`).

Only `.md` files are synced as notes; hidden folders (`.obsidian`, `.trash`) are skipped. Images, PDFs, audio and video are listed separately (`GET /api/attachments`) and read one at a time (`GET /api/attachment?path=`), read-only. Folders and files named in `EXCLUDE` in `wrangler.toml` (for now `_includes/`, the site templates, and `content/404.md`, the site's not-found page) are refused by the Worker itself: never listed, read, written or deleted.

`dataviewjs` blocks run and show their output in place of the code, like the Dataview plugin (`src/dataview.js`); **</>** or moving the cursor into a block shows the script. Each block runs in `public/dv-sandbox.html`, loaded in a sandboxed iframe with its own opaque origin: it can't see the token, storage or the page, and its CSP allows no network. It gets its note's Dataview page (`src/dvpage.js`: frontmatter fields, `file.lists` with their headings, and so on) plus the pages of notes in the same folder or linked from it, and asks the app for anything else: `dv.io.load` and `app.vault.read` read notes on the device, and `requestUrl` fetches public pages through `/api/fetch`. Scripts can't write: `vault.modify` fails with a message and `processFrontMatter` does nothing, so notes only change when you edit them. The one exception is ticking a box in a `dv.taskList` or a `TASK` query's results: that ticks the task's real line in its note (found at its line, or by its text if the note has moved on), adding or removing the done date as ticking it there would. A script can't do this on its own; the app only accepts a tick during a click. A script that calls `dv.pages()` gets every note's page instead (sources like `"folder"`, `#tag`, `[[note]]` and `outgoing([[note]])`, joined with `and`, `or` and `-`), with Dataview's `DataArray` methods (`where`, `sort`, `groupBy`, `map`, field swizzling), dates as a Luxon-like `DateTime` (`toFormat`, `plus`, `diff`), `file.link`, `file.day`, `file.tasks`, `file.inlinks` and `file.outlinks`, and note links in the output that open the note. Plain ```` ```dataview ```` query blocks (`TABLE`, `LIST`, `TASK` with `FROM`, `WHERE`, `SORT`, `GROUP BY`, `FLATTEN`, `LIMIT` and Dataview's common functions) are read by `src/dql.js` and drawn by the app itself; they're interpreted, not run as code, so they need no sandbox. Inline `= expr` fields and `CALENDAR` queries aren't supported. Blocks in `_clippings/` and `_uploads/` never run, since that text comes from outside the vault. **Recipes:** the Recipe template's **Sync to Nutrition Database** block is the one script that writes, so wr1t3r does that one itself (`src/recipe.js`, `src/recipeview.js`): in its place it shows the recipe's per-serving numbers and whether the database has them (missing, up to date, or with older numbers), and the button adds or updates the recipe's row the way the template's script does, the same ingredients, matching, rounding and row, keeping any aliases added to the row by hand.

**Folding Dataview blocks:** the ▾ beside **</>** folds a block, and blocks with only blank lines between them (like the daily note's calorie, hydration, steps and activity meters) fold together into one line that shows each block's label and numbers (`🎯 Calories 1200 / 2000 cal (50%) · 💧 Hydration …`); click it to unfold. It's remembered per device and follows the blocks' code, so every daily note made from the same template opens folded or not alike. The note isn't changed.

**Bases** (`.base` files) open as their views instead of their YAML, and ```` ```base ```` blocks in a note show the same way while the cursor is outside them (`src/bases.js` works them out, `src/basesview.js` draws them). A base picks notes with `filters` (expressions like `file.inFolder("content/logs/books")`, `file.hasTag("crit")`, `shelf.contains("Finished")`, `date > today() - "30 days"`, joined with `and`, `or` and `not`), and each of its `views` shows them as a **table** (a grid), **cards** (a gallery, with `image:` as the picture), a **list** or a **kanban** board, with the columns in `order`, sorted by `sort`, grouped by `groupBy` and cut at `limit`. `formulas` add computed columns (`formula.pace` = `pages / length`), with the common functions and methods (`if`, `date`, `now`, `today`, `link`, `number`, `.contains`, `.format`, `.round`, `.lower`, `.join` and so on). `properties` give columns their display names.
- **Set up from the screen**, the way Anytype sets work: the toolbar over a base has **Source** (the folders and tags its notes come from), **Properties** (tick what shows, drag to reorder), **Filter** (rows of property, condition and value, matching all or any; the conditions depend on the property: text, number, date, list or checkbox), **Sort** (several levels, or **binder order**, the corkboard's order from each folder's `_Binder.md`), **Group** and **Layout**. Every change is written into the base's YAML in the standard Bases keys (`filters`, `order`, `sort`, `groupBy`, `columnSize`, `image`, `cardSize`, `imageFit`, `imageAspectRatio`, `limit`), so it's the same on every device; what the format has no key for (kanban lane order, hidden lanes, binder order) goes under the view's `wr1t3r:` key. Filters made in the menus are plain expressions (`shelf.contains("Reading")`, `pages > 300`); hand-written ones still work and show as their own rows. Undo takes a change back. Comments in a .base file are lost when wr1t3r rewrites it.
- **Views** are tabs: **+** adds one, and a tab's ▾ (or right-click, long-press) renames, duplicates, moves, deletes it or changes its type. The open tab is remembered per device. Clicking a column head sorts by it for now; **Save sort** puts that into the view.
- **Grid** (a table): drag a column head to move it, drag its right edge to size it (double-click the edge to undo). **Gallery** (cards): a cover from any property, three card sizes, fill or fit, and a shape; notes without a cover show their initial, colored by a `label` of 1 to 7 as on the corkboard. **List**: one row a note, its values as chips. **Kanban**: lanes are the values of one property (Layout > Lanes from); drag a card to another lane (long-press on a phone) or use its ⋯ menu, and that value is written into the note. A list property swaps just the one value. Lanes can be dragged by their heads, hidden, or added before any note has the value; **+** in a lane makes a note already in it.
- **Editing values**: click a note property's value in any layout. Checkboxes toggle, dates get a date picker, numbers stay numbers, lists are chips with a box that suggests values other notes use, and text suggests them too. Only that property's lines change in the note. `file.` columns and formulas are read-only, and so are a table row's own columns (see Budgets with boards).
- **+ New** makes a note in the base's source folder (or the base's own), with what the filters ask for already set (`shelf.contains("TBR")` gives it `shelf: [TBR]`), and opens it.
- Links to web images show as pictures: any `https://` address ending in an image type, and any web link in a property named like cover, image, poster or thumbnail.
- `</>` shows the base's YAML to edit; **Show base** goes back. **New** with a name ending in `.base` starts a new base (a table of every note).
- Map and calendar views, column summaries, hand-picked collections, `file.ctime`/`file.mtime` (the vault doesn't keep them) and embedding a base with `![[Books.base]]` aren't supported yet.

**Today** opens today's daily note, `daily/YYYY-MM-DD.md`, or makes it from `_templates/Daily.md` (`src/daily.js`). The template is filled in the way Templater does it (`tp.date.now`, `tp.file.title`), and its script block is read rather than run: it makes the companion `YYYY-MM-DD Health` note from `_templates/Daily Health.md` and writes the link to it. Nothing in a template is ever executed.

**Daily note timeline:** pick a calendar under Settings > Tasks and daily note > Timeline calendar (off until you do; per device) and Today puts that day's events into the note's `# Timeline` section as tasks, whether it makes the note or opens one that already exists (made earlier, or elsewhere), `- [ ] 09:30 - 10:15 | Dentist` or `- [ ] All day | Trip`, and the Timeline's items are sorted by start time: all-day first, anything you added there included, with lines indented under an item moving with it, and an item with no time staying under the one above it (`src/timeline.js`). An empty slot an event covers is replaced by it; slots you've written in are left alone. For a note made elsewhere, or events added later, run **Add calendar events to the timeline** from the command palette: it fills the open daily note (or today's), and skips events already listed, so running it twice changes nothing. A moved event is added at its new time and the old line stays. On a planner page the events go into the planner's Timeline instead (`HH:MM - HH:MM | Title` entries in its `timeline:` list), skipping ones already there.

**Manuscripts (Scrivener-style folders).** Any folder can open as its own tab (right-click or long-press it in the sidebar, or **Open storyboard / outliner / draft** in the command palette), shown one of three ways, remembered per folder:
- **Storyboard** (called corkboard in the code and in `corkboard:` pins, which still work, as do `storyboard:` ones): an index card per note, on a dot-grid page, with its title (first `#` heading, else `title:`, else the file name), its `synopsis:` (or, dimmed, the start of its text; click to write one), a `label:` color strip (1-7, the theme's rainbow), its `status:` and word count. Subfolders are stacks: click one to open it, or drop a card on its middle to move the note in. Drag cards into order with a mouse, or hold a finger on one and then drag; a hold without moving opens its menu. Alt+Arrow keys move the focused card.
- **Outliner**: the same notes as rows (title, synopsis, status, words), subfolders nested and foldable, synopsis and status editable in place, the dot sets the label. Rows drag into order, and into or out of subfolders.
- **Draft**: every note in the folder (subfolders too) as one long document. Each section is its own editor and saves to its own note like any edit; properties start hidden; arrow keys run on from one section into the next. Only the sections near the screen get an editor, so a long manuscript stays quick.

The order lives in the folder, in a note called `_Binder.md`: a numbered list of `[[links]]` (and `[Part Two](Part%20Two/)` for subfolders), made the first time you reorder. Editing the list by hand reorders the folder too. Notes it doesn't list yet come last, alphabetically. Renaming or moving a note rewrites the binder's link without asking, so the order holds. With a binder, the sidebar lists that folder in the same order and hides the binder itself (**⋯ > Open the binder note** shows it). `src/binder.js` reads and writes it; `src/folderview.js` and `src/scrivenings.js` draw the views; `src/cards.js` and `src/drag.js` are the card and the mouse-and-touch drag the views share.

**New project**: the Project button in the sidebar (or **New project** in the command palette) asks what you're writing: a short story, novel, essay (plain, or a research paper in MLA, APA or Chicago style) or script (screenplay, TV episode or comic), then its title. It makes a folder named for it with starter notes from the writing templates (a notebook's own `_templates/` note of the same name wins), a `Notes/` subfolder of planning notes marked `compile: false` (character sheet, outline, style sheet, sources, beat sheet or series bible), and a `_Binder.md` with the order and Compile settings, then opens the storyboard (`src/projects.js`).

**Writing templates** (`src/builtintemplates.js`): Scene, Chapter, Character, Style sheet, Essay, Research paper (MLA / APA / Chicago, each with its style's layout and citation formats in `%% comments %%`), Script scene, Screenplay, TV script and Comic script. They're listed in Settings > Templates, the slash menu and Insert template beside the notebook's own until it has one of the same name; **Make my own copy** puts one in `_templates/` to change.

**Script layout**: a note with `script` (or `screenplay`) in its `cssclasses` is laid out as a screenplay in Courier: scene headings (INT./EXT.), action, a character's name in capitals with dialogue and (parentheticals) under it, and transitions (CUT TO:) on the right, written as plain lines the way Fountain does. Compile has a matching **Script** layout for HTML, PDF and Word, picked by itself when the notes ask for it (`src/script.js`, `src/scriptview.js`). A folder whose notes are all left out of Compile gets no heading.

**Manuscript layout**: a note with `manuscript` in its `cssclasses` property is shown double-spaced with the first line of each paragraph indented, in the editor and in Draft view. Nothing is added to the text, so the file stays exactly as written (`src/manuscript.js`, `src/manuscriptview.js`).

**Compile** (the folder bar, the folder's menu, or the palette) joins the folder's notes in binder order into one file, with a live preview: Markdown, HTML (a self-contained, book-styled page), PDF (the browser's print dialog, "Save as PDF"), or Word (.docx). It takes an optional title and author (for a title page), note titles as headings or text only, and a scene break (`* * *`), blank line or new page between notes. Properties, `%% comments %%`, HTML comments and block ids are left out, `[[links]]` become plain words, `![[note]]` embeds are inlined, vault images go in the HTML, PDF and Word versions, and footnotes are renumbered across the whole document. Notes with `compile: false` or `status: cut` are skipped. **Layout** is Book or Manuscript (Times, double-spaced, first line of each paragraph indented half an inch, each line of prose its own paragraph); it starts on Manuscript when a note in the folder has `cssclasses: [manuscript]`. The settings are saved in the binder's `compile:` property. **Save to vault** keeps the markdown as a note in `_compiled/`. The converters (markdown-it, docx) load only when Compile opens (`src/compile.js`, `src/exporter.js`, `src/compileview.js`).

With no note open, the main window shows a quote about writing or making art that changes at local midnight. The list is in `src/quotes.js` and ships with the app, so it works offline; add or remove lines there to change the rotation. Under it is a writing prompt question, also one a day (`src/prompts.js`, 60 of them). Tap it to start a journal entry for it in `journal/`, titled with the prompt and with the frontmatter from `_templates/Journal.md` (you can change the name first), or tap ↻ for another prompt.

**On this day** sits under the prompt when something was written on today's date in an earlier year: daily notes with words of their own (an empty planner page doesn't count), notes named by their date (`2024-05-03 Lake trip`, as Day One imports are), and notes in a `journal` folder by their `date:` property. **Mood, sleep and weight** (the palette, or Planner > Mood, sleep and weight… on a daily note) charts what the planner's buttons logged in the health notes over the last 30 days, 90 days (by week) or year (by month): a strip of each day's mood with a count of each, sleep as a line with the average, average sleep on the days of each mood, and weight with its change. Right-click or long-press a header to rename, move or remove it (its tiles stay). Headers don't change the tiles' automatic colors. **Pinned to daily notes** are cards that sit at the top of every daily note (a note named `YYYY-MM-DD`), under its properties, until you unpin them. **Cards in a note** (`src/cardsblock.js`): **Cards** in the slash menu adds a ```` ```wr1t3r-cards ```` block, which shows as the same tiles while the cursor is outside it, with the same menus (color, cover, rename, move, sections, remove), dragging and **+**. **The Planner** (`src/planner.js`, `src/plannerview.js`): **Planner** in the slash menu adds a ```` ```wr1t3r-planner ```` block and a `# Notes` heading under it; with them in `_templates/Daily.md`, Today makes every daily note a planner page. The block shows the day's title (a `banner:` picture above it if set), the health buttons that write to the day's health note (`YYYY-MM-DD Health`, made from `_templates/Daily Health.md` if it isn't there yet), then the **Timeline** beside the Critical Tasks and To Do's lists. The note's properties box is hidden on a planner page; **Properties** in the planner's header shows it, and **Health note** opens the health note.
- **Food** searches the vault's `Nutrition Database.md` table (names and aliases) and logs `- Banana, 1` under the meal's heading (`### 🍳Breakfast` and so on), with the servings you set. A food that isn't there yet: **Search USDA** looks it up in USDA FoodData Central (`worker/usda.js`; the key is the Worker's `USDA_API_KEY`, see [USDA food search](#usda-food-search)), and picking a result adds it to the table as a new row (for one serving: the label's for a branded food, else USDA's first household measure) and logs it. **Water** adds `- 8` (fl oz) under `### 💧 Water` on each click; right-click or long-press it to take the last one back. **Meds** counts the day's doses from the medicine list (below); with no list it flips `meds:` between true and false. **Sleep** logs `- 23:10 - 06:40 | 7.5 h | note` under `## 😴 Sleep`. **Weight** logs `- 07:05 | 208.4 lb` under `## ⚖️ Weight`, shows the change since the last weight logged, and offers to work the targets out again once it's 5 lb (2.5 kg) from the goal's. **Exercise** logs `- 07:30 | 🚶 Walk | 3200 steps | 150 cal | note` under `### 🏃 Exercise`. **Mood** logs `- 14:32 | 🙂 Good | note` under `## Mood Log`. The Food, Exercise and Mood panels list the day's entries with × to remove one.
- **Filling the Nutrition Database:** with no database, the Food panel's **Make one** writes `Nutrition Database.md` (beside `Medications.md`, else in the notes' folder) with an empty table. Commands > **Import foods into the Nutrition Database** reads a CSV with a header row (`src/foodimport.js`; columns matched by name: Food/Name, Calories/Energy (kcal), Serving Size, Fat, Carbs, Protein, Fiber, Food Group, Aliases) and adds the foods it doesn't have yet. Commands > **Add this recipe to the Nutrition Database** does what the Recipe template's sync button does for the open note: its `## Ingredients` list (`Food, servings`), per serving of its `yield:` (`src/recipe.js`). Ingredients the database doesn't have are first looked up in the shipped USDA tables (`closestFoods` in `src/recipe.js`: words weighted by rarity, the plain raw form preferred over dishes), and a dialog (`src/ingredientview.js`) offers the five closest for each, showing their servings; each pick is added with the ingredient's name as an alias. The template's button gets a **Find them in USDA foods** link doing the same. The **📷** at the end of the Food panel's search box (and Commands > **Add a food from a nutrition label photo**) takes a photo of a package. A barcode in it is read first (`src/barcode.js`: the browser's `BarcodeDetector` where there is one, else ZXing, `@zxing/library`, loaded only then); a food in the database with that barcode as an alias is logged as is, else Open Food Facts is asked for it from the page (`src/openfoodfacts.js`; no key, so it works on every build; `https://world.openfoodfacts.org` is in `connect-src`), and the food comes back with the barcode as an alias. With no barcode, or one Open Food Facts doesn't know, it reads the photo of a Nutrition Facts label on the device with the same Tesseract setup as searchable pictures (`src/localocr.js`), picks the numbers out (`src/label.js`, which also fixes the usual misreads: O for 0, a g read as 9), and shows them beside the photo in a form to check and name (`src/labelview.js`) before the row is added. wr1t3r.app/health-data.html#foods explains all of it.
- **Planner** (in the header) has **Choose buttons…** (which of Food, Water, Meds, Exercise, Mood, Sleep and Weight show, and their order), **Set my targets…**, **Medications…** and **Set up the planner…**. A planner not set up yet shows a card that walks through the same steps; finishing it or **Not now** writes `setup: done`. These settings are saved in `_templates/Daily.md`'s planner block (made from the built-in template if the vault has none), so every day, old and new, uses them; a day's own block can still set any of them for that day.
- **Targets** (`src/targets.js`): from sex, age, height, weight, activity, a goal (lose 1 or ½ lb a week, stay, gain ½ lb) and a pregnant-or-breastfeeding tick, for adults (18+) only. Calories are the Mifflin-St Jeor resting rate times the activity level, less 500 or 250 or plus 250 a day (no cut while pregnant), never under 1,500 (male) / 1,200 (female) / 1,350. Water is the National Academies' intake from drinks (101 oz men, 74 oz women, 88 oz otherwise) to the nearest water step. Steps are 8,000 under 60, 7,000 from 60. With **Protein, fat and carbs targets too** on (`macros: true`): protein in g per kg of the weight that's a BMI of 25 at most (0.8, or 1.0 at 65+, 1.1 pregnant, 1.2 while losing, 1.4 for hard training, whichever is highest, capped at 35% of calories), fat 30% of calories, carbs the rest, fiber 14 g per 1,000 calories; the Food panel shows each against its target. The sources are listed on wr1t3r.app/health-data.html (`site/pages/health-data.md`); keep it in step with the code. Until a goal is worked out, the targets are the Nutrition Facts label values: 2,000 calories, 50 g protein, 78 g fat, 275 g carbs, 28 g fiber, and 88 oz of water. Every number can be changed before saving. Kept as `goal: {units: lb, sex: male, age: 41, height: 70, weight: 210, activity: light, plan: lose-1}` (height in inches, or cm with `units: kg`; `pregnant: true` when ticked) and the `*_target` keys.
- **Medications** (`src/meds.js`): the list is `Medications.md` (or the note `medications:` names), one medicine a line, `- Lisinopril | 10 mg | 08:00`, `- Vitamin D | 1 tab | 08:00, 20:00`, `- Methotrexate | 2.5 mg | 09:00 | Mon`, `- Ibuprofen | 200 mg | as needed`; the Meds panel adds and changes these lines. Typing three or more letters of a name in its Add form searches the National Library of Medicine's RxTerms from the page (`src/rxterms.js`; no key, so it works on every build; `https://clinicaltables.nlm.nih.gov` is in `connect-src`; only the typed text is sent), brand and generic names alike; picking one fills the name and shows its strengths (`10 mg Tab`) as buttons for the dose. Anything can still be typed by hand. Each medicine in the list has a **Label** link to its DailyMed search (a plain link, nothing fetched). **📷 Photo of the pill** in the same form takes a photo (the camera on a phone; `src/photo.js`, shrunk to 1200 px), saves it where a picture pasted into the list note would go, named `Lisinopril pill.jpg`, and puts its embed at the end of the line (`- Lisinopril | 10 mg | 08:00 | ![[Lisinopril pill.jpg]]`), so other markdown apps show it in the list too. The photo shows as a small picture beside the medicine in the list and on each dose; tapping it opens it full size. Removing or retaking a photo leaves the old picture in the vault. **Take** logs `- 08:12 | Lisinopril | 10 mg | for 08:00` under `## 💊 Medications`, and the health note gets `meds` (true once every dose is taken), `meds_taken` and `meds_due`. A dose more than an hour late turns the button red. Each dose not yet taken is a reminder at its time for the next week, through task reminders (pushed by the Worker; in the Dropbox build, shown while wr1t3r is open), unless **Remind me at each dose's time** is off (`med_reminders: false`). A line can also carry `from 2026-10-20` and `until 2026-10-24` (a course: no doses or reminders outside it, and as-needed ones hide too), `purpose: Prevents nausea` and `note: Avoid dairy 2 h before and after`, anywhere after the name; the Add form has fields for each. **Medication chart** (`src/medchartview.js`, built by `medChart` in `src/meds.js`; the Meds panel's **Chart**, or right-click a Meds button): the list as a table like a clinic's sheet, a row per medicine (name, purpose, schedule and comments) and a column per time any of them is taken, plus As needed. **Day log** fills it in from the day's log: ✓ with the time and who gave it, X for a dose due (red once it's an hour late), – where the medicine isn't taken that day; ‹ › moves between days. **Blank sheet** has an X at each medicine's times and nothing logged, for printing and ticking by hand. **Print** prints either (landscape). **People you give medicines to:** Planner > **Someone else's medicines…** adds a name to the shared `people: [Mom]`, which gives that person a Meds button of their own. Their list is `People/Mom/Medications.md` and each day's doses are logged in `People/Mom/Meds/2026-10-13 meds.md` (same heading and lines, with `meds`, `meds_taken` and `meds_due` properties); their doses are reminders too, titled `💊 Mom: Lisinopril 10 mg`. The person's list editor can take the button off again (their notes stay). **Who gave it:** the Meds panel's **Add your name to doses** sets this device's name (`wr1t3rMyName` in localStorage), and each dose it logs ends `| by Sam`, shown as `✓ 8:12am by Sam`. **Sync before Take:** Take first syncs (`plannerHost.syncNow`, waiting up to 10 s; offline it says so and logs anyway), then asks before logging a scheduled dose that already has an entry, or an as-needed one logged in the last 30 minutes (`alreadyGiven` in `src/meds.js`), so two people sharing a vault don't both give it. Sync isn't live: two taps within the same few seconds on two devices can still both log. **On the calendar:** each list's scheduled doses show in the agenda and month calendar as their own calendar (`medsCalendar` and `medEvents` in `src/meds.js`): **Medications** for yours and **Mom's medicines** for each person, each with its chip to show or hide it. Each dose is a quarter-hour event, `💊 Lisinopril 10 mg` (`💊 Mom: …` on a person's), that turns into `✓ …` with when and by whom once it's logged. They're worked out from the lists and logs whenever the agenda draws, so they show with Google Calendar or the built-in one, offline too, and nothing is written to Google Calendar. They have no alerts of their own, since the dose reminders do that, and they can't be picked as the Timeline calendar. **Doses in Google Calendar:** with Google Calendar connected, Settings > Reminders > **Medicine doses in Google Calendar** sends the next two weeks of doses (yours and each person's) to a Google calendar as events with a popup, titled like the reminders (`💊 Mom: Lisinopril 10 mg`): **Same as reminders** (the default) puts them in the reminders calendar above it, a calendar of their own (make one called Medications) keeps them apart from task reminders, and **Off** sends none (`byCalendar` in `src/calreminders.js`; per device, `wr1t3r-med-calendar`). A dose logged with Take has its event taken back out. **Import from a spreadsheet…** (in the list editor, yours or a person's; `src/medimport.js`) adds medicines from a `.csv` or an `.xlsx`'s first sheet. Its header row needs a Medicine (or Name, Medication, Drug) column; Dose (Strength), Times (Schedule, Frequency), Days, Start, End, Purpose and Notes (Comments) are read when there. Times can be clock times or words (`once daily` is 8am, `twice daily`/`BID` 8am and 8pm, `TID`, `QID`, `at bedtime` 9pm, `as needed`/`PRN`); a schedule it can't read goes into the note and the medicine comes in as needed. A clinic chart's layout works as well: a column headed by a time with an X where the medicine's taken then, and an As needed column. Medicines already on the list (same name) are left as they are.
- After each change the health note's properties are worked out again from those lines: `calories`, `fat_g`, `carbs_g`, `protein_g`, `fiber_g`, `hydration_oz`, `steps`, `activity_kcal`, `mood` (the latest), `sleep_h`, `weight` and `weight_unit`, `meds`, `meds_taken` and `meds_due`, and their targets, which is what `_docs/Health Trends.md` charts.
- **Timeline**: an hour a row from 9 AM to 9 PM. Click a row to write in it, click an entry to change it (empty removes it), or type your own time (`10:30 - 11:15 | Dentist`). **Import** adds the day's events from the calendar picked under Settings > Tasks and daily note > Timeline calendar, skipping ones already there. Imported entries take the event's Google color (its own, else its calendar's), as a `{#039be5}` at the end of the line that the card turns into the entry's tint; importing again colors entries brought in before they had one, and changing an entry's text keeps its color. Right-click an entry (long-press on a phone) to pick its color from Google Calendar's eleven, or No color (the accent); that's how entries you type get one. The entries live in the block as `timeline:` lines.
- The block's other keys, all optional: `title:`, `tasks: [crit, todo]`, `moods: [😄 Great, 🙂 Good, …]`, `exercises: [🚶 Walk, 🏃 Run, 🥾 Hike]`, `buttons: [food, water, meds, exercise, mood]`, `calories_target: 2000`, `water_target: 88`, `water_step: 8`, `steps_target: 7000`, `activity_target: 400`, `sleep_target: 8`, `protein_target`, `fat_target`, `carbs_target`, `fiber_target`, `macros`, `goal`, `units: lb`, `medications:`, `med_reminders`, `setup`, `start: 9` and `end: 21` (the Timeline's hours), and `nutrition:` (another database note). **</>** shows them.
